# استعادة إيصال Health بعد فقدان قراءة نتيجة الحفظ

## سبب الإضافة

يحفظ Native بيانات الصحة وسجل العملية في معاملة واحدة، ثم يقرأ النتيجة في معاملة مستقلة. إذا تعذرت القراءة الأخيرة أو غادر المستخدم الشاشة قبل حفظ رسالة الإيصال، فقد تكون البيانات محفوظة بالفعل بينما لا توجد رسالة تحمل معرّف العملية لإعادة اكتشافها. إعادة إدخال الطلب بمعرّف جديد لا تمثل إعادة محاولة للعملية الأصلية.

أُضيف مرجع اختياري داخل **سجل Native الموجود نفسه**، من دون جدول أو سجل عمليات ثانٍ. يمرر تكامل الواجهة هوية المحادثة المحفوظة قبل بدء العملية، ويتحقق من حفظ الإيصال الفعلي قبل تأكيد استلامه. هذا الملف يشرح طبقة Native واختباراتها؛ اختبارات الواجهة موثقة في حزمة الاختبارات المخصصة لها.

## العقد البرمجي

```dart
Future<CoachNativeCommit> commit({
  required CoachNativeCommand command,
  required CoachNativeOwnerScope scope,
  void Function()? checkWritePermission,
  String? healthRecoveryConversationId,
});

Future<List<String>> listPendingHealthReceiptOperationIds({
  required CoachNativeOwnerScope scope,
  required String conversationId,
  int limit = 16,
});

Future<void> markHealthReceiptPersisted({
  required String operationId,
  required CoachNativeOwnerScope scope,
  required String conversationId,
});
```

عند تمرير هوية محادثة إلى عملية Health جديدة، يُضاف الحقل الآتي إلى JSON سجل العملية في معاملة حفظ بيانات الصحة ذاتها:

```json
"healthReceiptRecovery": {
  "conversationId": "synthetic-conversation-a",
  "receiptAcknowledged": false
}
```

هوية المحادثة غير فارغة، بلا فراغات طرفية، وطولها لا يتجاوز 256 محرفًا. الحقل اختياري ومتاح لعمليات Health فقط. إعادة العملية ذات المعرّف نفسه لا تعيد ضبط التأكيد ولا تنقل العملية إلى محادثة أخرى. السجل القديم الذي لا يحتوي المرجع لا يُعدّل لتخمين محادثته.

## خصائص الحفظ والاستعادة

- لا توجد قراءة إضافية لسجل العملية بعد كتابته داخل معاملة `commit`. أول قراءة تالية للسجل تظل قراءة النتيجة بعد الالتزام؛ لذلك يبقى وصف `committed: true` دقيقًا عند فشل تلك القراءة.
- يفحص البحث نطاق المالك والمحادثة، ونوع العملية الصحي، وتطابق مفتاح التفضيل مع معرّف العملية، والقيمة المنطقية JSON `false` قبل تطبيق الحد. تُحاط دوال JSON بشرط `CASE WHEN json_valid(value)` كي لا يوقف JSON تالف عملية البحث.
- يتحقق فك السجل من أمر Native الأصلي وهويته وبصمته قبل إعادة أي معرّف إلى الواجهة. لا يطبق البحث أمرًا أو تعويضًا أو إصلاحًا للبيانات.
- يجري التأكيد في معاملة مستقلة، مع فحص المالك قبل الانتظار وبعده. يحدّث قيمة الصف الموجود بشرط تطابق قيمته المقروءة، ويشترط تعديل صف واحد. يحافظ على `rowid` و`updated_at` ولقطات البيانات والبصمة والحقول الأخرى. لا يكتب شيئًا إذا كان الإيصال مؤكدًا بالفعل.
- تتولى الواجهة التحقق المستقل من أن الإيصال المطابق موجود في المحادثة المحفوظة قبل استدعاء التأكيد؛ لا تمنح علامة التأكيد أي صلاحية جديدة لتعديل الصحة.
- يحتفظ تعويض Undo بمرجع المحادثة وحالة التأكيد. يبقى ترتيب إدراج سجلات Native صالحًا لفحص منع التراجع القديم؛ ولا يعيد تأكيد إيصال قديم ترتيب العملية بعد عملية أحدث.
- يبقى ترميز السجلات التي لا تحتوي المرجع الاختياري مطابقًا بايتًا لشكله السابق، ويظل `argumentsDigest` قائمًا على الأمر ولقطته الأصلية.

## حدود واضحة

البحث محدود بأحدث 16 مرشحًا افتراضيًا، ويمكن طلب عدد من 1 إلى 32. تُستبعد المحادثات الأخرى والبيانات الوصفية التالفة قبل الحد، ولذلك لا تخفي العمليات الأحدث غير المرتبطة عملية أقدم مؤهلة. قد يستهلك سجل يطابق مرشحات JSON ثم يفشل فحص بصمته أو محتواه الكامل مكانًا من النافذة المحدودة؛ لا يقدم هذا العقد مسحًا شاملًا لكل السجلات التاريخية أو ضمانًا بإصلاح سجل تالف.

تبقى العملية التي لا يمكن التحقق منها غير مؤكدة، ولا تُعاد كتابتها أو تنفيذها تلقائيًا. كما لا تُخمن المحادثة لسجلات قديمة أُنشئت دون المرجع الجديد. تتطلب استعادة عرض النتيجة قراءة موثوقة لاحقة للبيانات والسجل.

## الأدلة المحلية

الاختبارات الجديدة في `test/parallel/bil04/health_receipt_recovery_test.dart` تستخدم قاعدة SQLite فعلية داخل مجلد مؤقت معزول. تشمل 20 حالة:

- فشل القراءة بعد الالتزام، ثم إغلاق القاعدة وإعادة فتحها واكتشاف العملية وقراءة نتيجتها من دون أي كتابة إضافية.
- إلغاء الصلاحية بعد كتابة السجل داخل المعاملة، والتراجع الذري عن البيانات والمرجع معًا.
- اكتشاف مرجع أقدم بعد 180 سجلًا أحدث لمحادثات أخرى، ووجود JSON غير مكتمل وبيانات وصفية بأنواع غير صحيحة ومالك أو معرّف غير مطابق.
- رفض محتوى سجل غير موثوق وحدود عدد النتائج وترتيبها.
- حفظ التأكيد بعد إعادة فتح القاعدة، وبقاء `rowid` والطابع الزمني واللقطات وصلاحية Undo، مع مشغّل SQLite يثبت أن التأكيد الثاني لا ينفذ UPDATE إضافيًا.
- بقاء البيانات الوصفية عند Undo قبل التأكيد وبعده، ومنع تأكيد عملية أقدم من إعادة منحها صلاحية Undo بعد عملية أحدث.
- رفض تغيير المالك أو المحادثة وتوقف التأكيد عند فقدان المالك أثناء القراءة.
- بقاء بايتات ترميز السجلات القديمة، ورفض إضافة المرجع إلى أمر غير صحي أو هوية محادثة غير صالحة.

بوابة Native تجمع الحالات العشرين مع **43 اختبارًا سابقًا** في `test/features/intelligence_center/coach_native_command_repository_test.dart`. الأوامر والنتائج وبصمات المصادر قبل التشغيل وبعده محفوظة تحت `health_receipt_recovery_validation/`:

**النتيجة النهائية: 63/63 اختبارًا ناجحًا، تحليل الملفات الأربعة بلا ملاحظات، وفحص التنسيق بلا تغييرات.** بقيت بصمات المصادر ثابتة طوال كل بوابة نهائية.

- `native_recovery_tests_final.json` و`native_recovery_tests_final.txt`.
- `native_recovery_analyze_final.json` و`native_recovery_analyze_final.txt`.
- `native_recovery_format_final.json` و`native_recovery_format_final.txt`.

حُفظت المحاولات السابقة أيضًا. فشل اختبار قديم للبايتات في المحاولة الأولى بسبب استخدام زمن UTC في تجهيز اختبار ماء يعتمد مساره القديم على زمن محلي؛ صُحح التجهيز فقط. وأُغلقت ثلاث ملاحظات أقواس في أدوات محاكاة الاختبار، من دون تغيير سلوك الإنتاج.
