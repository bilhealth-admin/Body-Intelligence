# BIL literal user-request traceability — 2026-09-06

## Purpose and source boundary

This is the literal-request ledger for the current BIL release work. It is not a
rewrite of an agent summary and it is not a claim that every item is complete.

- The live task log contains 454 records whose payload role is user. Filtering
  the message metadata to content_item_kinds containing user.text leaves **250
  actual user messages**; the other 204 records are injected environment,
  plugin, goal, or orchestration context.
- Those 250 messages were reduced only by merging exact repeats and by applying
  temporal precedence. The result is **93 distinct actionable product, UI,
  platform, account, store, QA, or release requirements** below.
- mcp__codex_app__read_thread was queried with page size 10 and pagination. Its
  recent page did not expose the active user-message bodies, so the authoritative
  fallback was the matching live rollout JSONL, filtered by user.text metadata.
  No image_url or base64 payload was decoded or copied into this document.
- U001…U250 are ordinals in that filtered stream. Dates are the UTC calendar
  dates from the message metadata. Screenshot names are included where supplied.
- Quotes are deliberately short but literal. HTML spacing entities were
  normalized. Insults, credentials, phone values, secrets, and personally
  identifying account strings are omitted or redacted.
- Evidence marked CONFIRMED-SOURCE proves only the checked source, contract,
  backend read-back, or console record named in that row. It does not silently
  imply a signed-device pass. CONFIRMED-RUNTIME is reserved for an observed
  runtime result on the named artifact/device.
- No source suite can prove “zero bugs worldwide” or guarantee Apple/Google
  acceptance. The current release decision remains governed by
  BIL_PREPRODUCTION_CONTRACT_AUDIT_2026-09-05.md and the clean-source freeze.

## Status vocabulary

- **ACTIVE** — latest instruction is being implemented or re-verified.
- **SUPERSEDED** — an older instruction was replaced by a later explicit one.
- **CONFIRMED-SOURCE** — implementation plus named source/contract/backend or
  console evidence exists; any remaining runtime boundary is stated.
- **CONFIRMED-RUNTIME** — the exact behavior was observed on the named runnable
  artifact/environment.
- **RESOLVED-CONDITIONAL** — a conditional request was resolved by supported
  feasibility evidence; this is not counted as an implemented login/feature.
- **OPEN** — still lacks implementation evidence or the requested proof.
- **BLOCKED** — cannot advance safely until the stated external, signed-build,
  clean-tree, or device prerequisite exists.
