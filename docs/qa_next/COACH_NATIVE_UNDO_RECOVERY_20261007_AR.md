# Coach — استعادة التراجع للأوامر غير الغذائية

## المصدر والنطاق

بُنيت هذه الدفعة فوق `32b225431b69bac5ce85e5e5de894e11d48fd031`؛ التغيير السابق له كان استعادة أدوات QA فقط فوق `877eb25cabba746a56e07508bc0570fe492dfebe`. الفرع الوحيد هو `qa/coach-community-next-20261005`. هذه الدفعة لا تعيد R5 أو Rewards من الصفر ولا تدّعي اكتمال Food V2 أو المطابقة البصرية.

## العطل المعاد إنتاجه

كانت عمليات الماء والوزن والهدف والقياسات والذاكرة تُحفظ في المستودعات بالفعل، لكن زر التراجع كان يعتمد على callback داخل ذاكرة الصفحة ويختفي بعد إعادة فتح المحادثة. شغّلت 19 حالة جديدة مع الحالات الثماني الأصلية قبل الإصلاح: 19 PASS و8 FAIL؛ الإخفاقات تخص استعادة التراجع، وليست دليل أن الحفظ الأصلي لا يعمل.

## التنفيذ

أضيفت `CoachNativeCommandRepository.readOperation` كقراءة فقط لسجل العملية وبياناتها الحالية ضمن معاملة قراءة واحدة. لا تنفذ prepare أو commit أو undo ولا تصلح السجل أثناء تحميل المحادثة. تفرق القراءة بين عملية قائمة أو معدلة أو متراجع عنها أو مفقودة، ولا تصف فشل القراءة بأنه كتابة جديدة التزمت.

تستعيد الصفحة زر التراجع فقط لإيصال BIL موثّق يطابق نتيجة المستودع: canonical tool، operation، arguments digest، entity type/id، وقت الالتزام، والنسختين before/after بما فيهما UUID. لا يكفي تشابه الرقم التسلسلي للصف أو النص المعروض. النسخ المكررة للعملية تعطي زرًا واحدًا؛ السجل الناقص أو الفاسد أو المعدل لا يُكتب فوقه ولا يعطّل إيصالات سليمة أخرى.

يرتبط callback المستعاد بزيارة المحادثة وهوية قاعدة البيانات والمستودعات والمستخدم وepoch/generation. تُلغى الزيارة عند A→B→A أو تبديل المستودع أو المحادثة أو مغادرة الصفحة، بما فيه أثناء انتظار قراءة السجل. يبقى Undo نفسه عبر المعاملة وCAS الأصليين؛ لا يعاد تنفيذ الأمر عند الفتح. مزامنة الذاكرة بعد التراجع تستخدم الحالة المحلية المقروءة والمالك الحالي، لا بيانات من نص المحادثة.

## الاختبارات المحلية

أضيفت **39 حالة**: 19 لاستعادة المحادثة، 13 لقراءة سجل العملية، و7 للحدود المؤجلة وهوية الإيصال. مع الحالات الأصلية أصبحت المجموعة **67 PASS / 0 FAIL**. يشمل ذلك الأنواع الخمسة، إعادة الفتح بعد Undo، تغير البيانات، سجل غير صالح، حسابًا آخر له integer ID مماثل، تغيير المالك أثناء القراءة وأثناء Undo، التخلص من الصفحة، تبديل المستودع، اختيار محادثة مختلفة ثم العودة.

المجموعة الأوسع في 15 ملفًا: **229 PASS / 0 FAIL**. تضم الحالات الـ67 وتختبر أيضًا admission والأذونات الحالية وأوامر الوجبات والاستعادة والذاكرة وتاريخ المحادثة وحياة صفحة Coach والسياق الغذائي والبنية والتوطين. الأعداد متداخلة ولا تُجمع باعتبارها اختبارات فريدة. لم تُحذف assertions قديمة؛ استخراج fixture إلى دالة mount قابلة لإعادة الاستخدام لا يبدل قيمه أو شروطه.

`dart analyze --fatal-infos lib` و`dart analyze --fatal-infos test/features/intelligence_center` بلا ملاحظات؛ `dart format` لا يطلب تغييرًا في ملفات الدفعة. بيئة Flutter 3.44.6 / Dart 3.12.2 وTZ=Africa/Cairo. جميع إصدارات الاعتمادات وبصماتها مقفلة بلا ترقية.

هذه النتائج المحلية تستخدم `--no-test-assets` وأصولًا أصلية مستعادة جزئيًا دون ملفات خطوط؛ هي إثبات سلوكي لا مطابقة بصرية. التحليل على الجذر المحلي كشف نقص أصول ثنائية وخطوط في الأرشيف، و`flutter analyze` المحلي يتعذر بسبب غياب SDK/dev؛ لم تُخفّض قواعد التحليل أو تُنشأ أصول بديلة لتزييف النجاح. فحص CI على checkout كامل مطلوب ولا يُستنتج نجاحه من هذه النتائج. تُحفظ الأوامر وتواريخها وبصمات السجلات في JSON المجاور.
